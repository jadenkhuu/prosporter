### What was refactored, and what it is worth

The LCP path was measured, not guessed. On the deployed build the client bundle
was ~180 KB transferred / ~576 KB parsed, of which:

- `mock-data/catalog.json` — 58 KB of product data — was shipped to the browser
  on **every route**, because `Header` was `"use client"` and imported
  `taxonomy` from `@/lib/catalog`, which loads `catalog.json` at module scope.
- the whole header (logo, nav, off-canvas menu and its three taxonomy lists) and
  the whole product card hydrated as client components.

So:

- **`src/components/layout/Header.tsx` is now a server component.** Three small
  client islands remain: `MobileMenuButton`, the existing `SearchDialog`, and
  the new `CartButton` (it needs the live line count). `MobileMenuPanel` is a
  client shell that supplies only the dialog behaviour — its nav lists are
  server markup passed as `children`, and a single delegated click handler on
  the panel closes the menu when a link is followed, so those links stay plain
  markup. Open/close state lives in `mobile-menu.ts`, a `useSyncExternalStore`
  module, because the hamburger sits in the header bar while the dialog has to
  stay a direct child of `<body>` (its `inertSiblings` treatment inerts the
  header, main and footer). `HeaderScrollShadow` is a headless island that
  toggles `data-scrolled` on `<html>`; the border-to-shadow swap is now CSS, so
  a scroll event no longer re-renders the header.
- **`src/components/product/ProductCard.tsx` is now a server component**, with
  `QuickAddButton` as the only client island. `PLACEHOLDER_IMAGE` moved to
  `placeholder.ts` so `ProductDetail` can reach it without importing the card.
  The grid still passes `sizes="(max-width: 640px) 50vw, …"` and `priority` for
  the first row unchanged.
- **The cart drawer is code-split.** `CartDrawerMount` loads it with
  `next/dynamic({ ssr: false })` from the root layout instead of from the
  header, so ~480 lines of client component leave the critical path. It is still
  *mounted* long before any shopper can click, so focus-in and focus-back to the
  opener are unchanged.
- The product page needed no change: the gallery's main image already had
  `priority` and `sizes="(max-width: 1024px) 100vw, 50vw"`, and the title and
  price are already in the server HTML (`ProductDetail` is SSR'd). `CartProvider`
  in `src/app/layout.tsx` renders `children` synchronously and does not defer
  paint.

Effect, measured:

| | client JS transferred | client JS parsed | script CPU (median) |
|---|---:|---:|---:|
| before | 181.6 KB | 576.0 KB | 282 ms |
| after | 179.0 KB | 535.7 KB | 277 ms |

`catalog.json` is gone from the client bundle (confirmed: no `primary_category`
in `.next/static`). Local medians over 3 runs against `next start` moved
home 3.33 s → 3.18 s, collection 2.65 s → 2.57 s, product 2.42 s → 2.27 s.

**Honest read: this is a real but small win, and it does not on its own close
D3 on home.** Lighthouse's bootup-time audit attributes ~205 ms of the ~280 ms
of script CPU to the React/Next framework chunk (71 KB), which ships regardless
of how few client islands the app has — `CartProvider` wraps the tree so the
runtime is always present. The refactor removes app code and 58 KB of JSON, not
the framework, so the expected Vercel improvement is on the order of 50-150 ms
of simulated LCP. Home was 2.60 s and needs ~100 ms; collection was 2.51 s and
needs ~10 ms. Both are inside the run-to-run spread (home's three runs after
07baeb2 were 2.60 / 3.12 / 2.39 s).

**Not done / next:** the refactor is not deployed, so there is no post-refactor
Vercel measurement. It needs a deploy and another 3-run pass on all three pages
before D3 can be called closed. If home still misses after that, the remaining
candidates are (a) `src/components/shop/Listing.tsx` is `"use client"` and
renders `ProductCard`, so the collection page still bundles the card — passing
pre-rendered card nodes into `Listing` would fix that, and (b) three woff2 faces
are preloaded at high priority and compete with the LCP image on the simulated
1.6 Mbps link; dropping the Archivo italic preload would free bandwidth but
risks CLS on the home `<h1>`.
