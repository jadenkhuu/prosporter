## Trailing slash

Every legacy URL on the WordPress site ends in `/`. Next.js normalizes the
trailing slash with its own 308 **before** it matches `redirects()`, and a
`source` written with a trailing slash is unreachable (verified: it 404s without
the slash and only ever 308s to the slash-free form). So sources are stored
slash-free, which is the only form that matches.

- Rows that cost one extra normalization hop when requested as `/path/`: **284**
- Rows that reach their destination or a 200 directly from `/path/`: 0

The redirect map itself has no chains; this is a platform normalization hop, not
a redirect chain in the map. To make legacy `/path/` requests land in a single
hop, strip the trailing slash at the CDN/edge before the request reaches Next.js
(the execution plan's "Next.js/edge layer"). Doing it inside the app instead
would mean `skipTrailingSlashRedirect: true` plus a proxy that handles both
forms, which changes trailing-slash behaviour for every route.
